## The Collection

**Fifty Projects** brings together fifty web projects created with HTML, CSS, and JavaScript. Each project is an opportunity to explore an idea, practice a technique, and turn a blank page into something that works.

The collection ranges from very simple components to somewhat complex applications. Some builds focus on layout and styling; others bring together user input, changing data, and multiple interactions.

> **Collection in progress:** The directory below is a tracker for the fifty builds. Project names, difficulty levels, links, and completion status can be filled in as each project takes shape.

## What You’ll Find

| Focus | What the projects can explore |
| --- | --- |
| 🧱 **Structure** | Semantic HTML, forms, and reusable page patterns |
| 🎨 **Presentation** | Responsive layouts, typography, transitions, and animation |
| ⚡ **Interaction** | Events, DOM updates, validation, and UI state |
| 🧩 **Problem solving** | Breaking larger ideas into smaller, manageable pieces |
| ♿ **Usability** | Keyboard controls, clear feedback, and accessible interfaces |

## Difficulty Guide

| Level | Scope |
| --- | --- |
| 🟢 **Very Simple** | A small component or focused effect with minimal logic. |
| 🔵 **Simple** | A complete widget with a few interactions or states. |
| 🟠 **Intermediate** | Several connected features, more involved logic, or persistent data. |
| 🟣 **Somewhat Complex** | A larger interactive build combining multiple concepts and UI states. |

Difficulty describes the scope of a project, not a required order. Explore whichever build catches your interest.

## Built With

- **HTML** gives each project its structure and content.
- **CSS** shapes the layout, visual style, and responsive behavior.
- **JavaScript** powers the logic and interactions.

Any project-specific dependencies, external services, or setup requirements should be documented in that project's own README.

## Getting Started

1. Download or clone this repository.
2. Choose a project folder from the collection.
3. Read that project's README for any setup instructions.
4. Open its `index.html` in a modern browser, or use a local development server when required.
5. Explore the code, make a change, and see what happens.

Projects using JavaScript modules, fetched files, or external APIs may need a local server or additional configuration. Keep private credentials out of browser code and the repository.

## Suggested Repository Layout

```text
fifty-projects/
├── README.md
├── LICENSE.md
├── 01-project-name/
│   ├── index.html
│   ├── style.css
│   ├── script.js
│   ├── README.md
│   └── assets/
├── 02-project-name/
│   └── ...
└── 50-project-name/
    └── ...
```

Numbered folders keep the collection easy to browse. Each project README can include a short description, screenshot, difficulty level, features, setup steps, and lessons learned.

## The Build Checklist

Before marking a project complete:

- [ ] The main features work as described.
- [ ] The layout works on narrow and wide screens.
- [ ] Interactive controls are labeled and usable with a keyboard.
- [ ] Empty, invalid, and unexpected inputs receive useful feedback where applicable.
- [ ] The browser console has no unexplained errors.
- [ ] The project README explains how to run the build.
- [ ] Third-party assets and sources receive appropriate credit.
- [ ] The directory entry has an updated name, difficulty, link, and status.

## Explore, Experiment, Improve

Use the collection to practice, revisit a concept, or try a different approach. Small changes can teach a lot: restyle a component, add keyboard support, simplify a function, or extend a project's behavior.

Suggestions and contributions are welcome. When proposing a change, explain what it improves and how to check it. Include screenshots for visual updates when helpful.
